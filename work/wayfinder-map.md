# 独立 Transformer 实验路线图

## 目标与范围

在当前 M5 MacBook Air 上，独立实现和训练一个小型 Transformer 语言模型，使用公开的 TinyStories；Tokenizer 自行在训练数据上训练完整的 Byte-level BPE，使用成熟的 `tokenizers` 实现 BPE 算法。模型从随机初始化开始，不加载 Checo 权重。最终以本机真实记录完成任务 A（训练与推理优化）及任务 B（训练动态受控实验）；不伪造训练或故障经历。

## 已确认约束

- 设备：M5、16GB 统一内存、8 核 GPU；可用磁盘约 30GB。此前只验证过 MLX 推理，训练稳定性待实测。
- TinyStories 数据集固定 revision `f54c09fd23315a6f9c86f9dc80f725de7d8f9c64`；训练与验证 split 分开，记录数据集来源及许可。
- 全新目录 `my-transformer/`，不修改现有 `llm-from-scratch/` 及其权重。
- 训练模型、数据预处理、训练入口、报告独立编写。Transformer 公共原理、MLX 和 tokenizers 库属于外部基础设施，不能声称独创。
- 生成内容、模型效果与耗时不预设；以记录为准。训练中的中断、内存和磁盘风险必须有明确处理。

## 架构契约

1. `prepare_data.py`：使用数据集 train split 训练 Byte-level BPE，完整字节覆盖；验证集不参与分词器训练。原文每篇故事独立编码、单次 BOS/EOS；以小端 uint16 写入 `artifacts/data/train.bin`、`val.bin`；记录 tokenizer、版本、故事和 token 计数、散列与格式。处理数据以分块方式进行，避免将全量 token 存在 Python 列表。
2. `model.py`：`GPTConfig(vocab_size=10000, context_length=512, n_layer=8, n_head=8, n_embd=512, ffn_hidden=3072)`；`GPT(config)`、`model(tokens, last_token_only=False)`。模型包含 token/position embedding、causal multi-head attention、RMSNorm、GELU MLP、残差、LM head；训练返回 `[B,T,V]`，仅最后位置推理返回 `[B,1,V]`。
3. `train.py`：仅新建或显式恢复本项目 checkpoint；训练指标以 JSONL 保存，固定验证切分，写明数据和 token 预算；checkpoint 包含模型、AdamW 状态、随机状态、步数和学习率计划，验证恢复轨迹；对内存和中断作真实记录。
4. 推理与评价：固定 tokenizer 和提示词；单独对比全位置投影与最后位置投影，先核对输出 logits，再计时，不把算子加速冒充端到端加速。
5. 任务 B 候选：从同一个本机训练 checkpoint 分叉，在相同模型、优化器和 token 预算下比较较小与较大训练数据池，记录训练阶段、真实 token 覆盖和独立验证集结果；先检查不同数据池的内容关系和评估口径。具体实验步数根据本机预检速度设定，不编造结果。

## 里程碑及门槛

1. 项目和数据：创建隔离环境；下载公开训练/验证集；训练 tokenizer 并编码；用样本检查往返、特殊 token、分割、格式和清单。
2. 模型与训练：实现上述接口；检查因果性、loss 梯度与 checkpoint 恢复；先对小数据完成短试跑，再从随机初始化开展正式训练。短试跑与正式训练单独记账。
3. 任务 A：至少一个真实 GPU 推理优化对照；记录完整训练链路、实际问题及处理；解释未验证处。
4. 任务 B：记录问题、假设、变量和预算；执行两组训练对照；发生预期冲突时先查测量和实验设计，再评价假设。
5. 交付：从本机日志、checkpoint 和生成样例编写两份报告；技术复核模型流程、数据来源、计算预算、失败与限制；验证报告和文件完整性。

## 风险与决策

- 精确重现实验需要模型、优化器、随机数和数据位置一起恢复；不同硬件或数值核可能仍非逐位一致。
- M5 Air 持续训练速度、内存占用和温度尚未测量。先做实际短试跑，再决定安全的微批次与正式训练步数；不以作者 M4 的时间作为本机实测。
- 实验期间保留原有其他目录和下载权重。数据及 checkpoint 增长前核对磁盘，不静默删除用户文件。
- 完整 Byte-level BPE 使用外部高性能库，模型及数据流水线由本项目实现；报告中注明而非声称算法和训练语料原创。

## 任务 A：最终权重的推理优化对照

- 主训练完成后，使用 A 组第 10,000 步权重与 `artifacts/data-clean/val.bin`，在 MLX GPU 上实际比较完整输出投影与只投影最后位置；没有重新训练，也未修改权重。结果文件：`experiments/inference-final.json`。
- 固定验证 token 流前 128 个 token，贪心生成 64 个 token；两种路径各预热 2 次，交替测量 10 轮。基线生成循环耗时中位数 `0.438394` 秒，优化后 `0.402447` 秒，吞吐分别为 `145.99` 和 `159.03` token/秒，本次吞吐提升约 `8.93%`。
- 初始输入最后位置的 logits 最大绝对差 `7.63e-6`，在 `rtol=1e-4`、`atol=1e-4` 下满足 allclose；两条路径生成的 64 个 token ID 完全一致，且本次生成未出现 EOS。
- 限制：结果仅覆盖一个固定输入与一次本机测量；输入片段含两个 BOS 和一个 EOS，跨故事边界。基准强制固定生成数量，不计权重加载、分词和文本解码；未记录每轮原始耗时或排除其他程序的 GPU 争用。`generate.py` 在此次实验前已使用该优化，结果不应表述为这次实验让现有程序又变快了。
