# Technical Report：学习率预热对 Transformer 训练动态的影响

- **实验类型：** Training Dynamics 受控对照
- **报告日期：** 2026 年 11 月 14 日
- **实验环境：** 本机 Apple Silicon、MLX
- **协作说明：** 本项目的代码编写、实验设计、运行和分析使用了 AI 协助。本文的数值来自本机实际训练日志及检查点，不是模拟结果。

## 摘要

我想知道：如果两个模型从相同初始状态和数据出发，只有前 500 步采用不同学习率路径，而之后尽量使用相同的学习率，这种早期差异会不会持续影响后面的训练？

我比较了两组各训练 10,000 步的约 4,411 万参数 Transformer：A 组前 500 步线性预热，B 组从最大学习率开始、前 500 步缓慢下降。两组第 501～10,000 步的实际学习率逐步一致。第 10,000 步，在相同固定抽样验证口径下，A 的 loss 为 **1.428095**，B 为 **1.919714**，B 高 **0.491619**。

B 的前几步训练 loss 下降反而更快，但到第 500 步，B 的验证 loss 已明显高于 A；此时第 501 步的学习率上跳尚未发生。这个结果支持“当前设置中的早期学习率路径会影响后续训练轨迹”，但不足以证明具体机制，也不能推广为“所有模型都必须预热”。B 的第 501 步存在一次约 0.617% 的学习率上跳，实验方案也在看过早期记录后修订，因此最终差异不能被无条件地称为纯预热效应。

## 1. 研究问题与假设

### 问题

在相同模型、初始化、数据和训练步数下，**前 500 步采用预热或不预热，会不会改变训练前期的 loss 变化，并且这种差异能否在后续学习率相同时持续到第 10,000 步？**

我关心的不是挑出一个更好的学习率数字，而是训练早期的路径是否会影响模型此后的状态，即训练过程的路径依赖。

### 事先假设

我的工作假设是：前期预热可能减小训练 loss 的变化幅度，并让最终验证 loss 更低。我的理由是，随机初始化的模型和优化器刚开始调整时，过大的学习率可能让早期参数更新不合适，从而影响后续轨迹。这是待验证的解释，并不是已知机制。

竞争解释同样合理：不预热可能在前期下降更快、整体仍然稳定；或者两组即使早期不同，后续也可能逐渐收敛到接近的结果。

## 2. 实验设置

| 项目 | 设置 |
|---|---|
| 模型 | 随机初始化的自回归 Transformer，约 44,110,336 个参数 |
| 结构 | 8 层、8 个注意力头、隐藏维度 512、MLP 隐藏维度 3,072、上下文长度 512 |
| 数据 | 公开 TinyStories；固定数据集 revision，BPE tokenizer 词表大小 10,000 |
| 验证数据 | 去除与训练集原文完全一致的验证故事；近似重复未检查 |
| 优化器 | MLX AdamW，weight decay 0.1，峰值学习率 0.0006 |
| 每次更新 | micro-batch 5，梯度累积 8，每步 20,480 个目标 token 位置 |
| 预算 | 每组 10,000 步，共 204,800,000 个训练 token 位置；位置允许重复，不等于独立 token 数 |
| 验证 | 每 100 步，用固定验证种子抽样，共计 25,600 个目标 token 位置；不是完整验证集 |
| 随机状态 | 训练采样 seed 2026；验证采样 seed 314159 |

两组使用相同的数据来源记录及相同的模型结构。B 从 A 的第 0 步检查点分叉；启动核验显示，A、B 初始模型、优化器和 MLX 随机状态共 255 项张量逐字节一致，NumPy 采样状态也一致。事后检查第 0、1,000、5,000 和 10,000 步检查点，这些时点的 NumPy 训练采样状态与数据来源记录一致；日志没有逐步保存每个采样索引，因此我不能声称已经逐条审计每个 batch。

### 学习率条件

| 阶段 | A：预热 | B：不预热 |
|---|---|---|
| 第 1 步 | 0.0000012 | 0.0006000 |
| 第 1～500 步 | 从低到高线性增加 | 从峰值开始，按余弦曲线缓慢下降 |
| 第 500 步 | 0.0006000 | 约 0.000596321 |
| 第 501 步 | 0.0006000 | 0.0006000 |
| 第 501～10,000 步 | 余弦下降 | 与 A 每一步相同 |

我逐步检查了两份实际日志：两组各有连续的 10,000 条训练记录和 100 条验证记录；第 501～10,000 步的学习率逐步相等。B 在第 500→501 步上跳约 **0.617%**。前 500 步学习率的累计和分别为 A 的 **0.150300** 与 B 的 **0.299386**；这是计划的数值差异，不等同于实际参数更新量。

## 3. 实验中的设计问题与修订

我实际遇到的问题不是程序崩溃，而是**最初的对照设计控制得不够严格**。

最初 B 的计划是全程使用无预热余弦下降，而 A 的余弦下降只覆盖预热后的阶段。检查学习率公式后，我发现即使过了第 500 步，两组的学习率仍会不同。这样若最后 loss 不同，我就无法把“前期路径不同”和“后期学习率也不同”分开讨论。

在 B 已开始训练、早期训练与验证记录已经可见之后，我与 AI 讨论并修订方案：保留 B 前 500 步原曲线，从第 501 步接入 A 的曲线。为了应用新计划，B 在第 236 步主动安全保存，随后从该步恢复；修订前后的 255 项模型、优化器和 MLX 随机状态张量逐项一致，NumPy 随机状态及数据来源也一致。这个主动中断不是训练故障。

修订改善了后期学习率的一致性，但引入了第 501 步的小幅上跳；而且修订发生在早期结果已经可见之后，所以这不是对 B 结果完全盲法预注册的实验。我保留了最初计划和修订记录，没有把这次变更当成从一开始就确定的方案。

## 4. 实验结果

### 4.1 验证 loss 的变化

下表的 loss 均来自同一固定抽样验证口径；B−A 为同一步两组 loss 的差。

| 步数 | A 验证 loss | B 验证 loss | B−A |
|---:|---:|---:|---:|
| 100 | 4.243949 | 5.191166 | 0.947218 |
| 500 | 2.721149 | 3.999645 | 1.278496 |
| 1,000 | 2.148474 | 3.811352 | 1.662878 |
| 2,000 | 1.837079 | 3.360391 | 1.523312 |
| 5,000 | 1.568854 | 2.226705 | 0.657851 |
| 10,000 | 1.428095 | 1.919714 | 0.491619 |

两组的验证 loss 都下降，B 并不是没有学到东西。在本次固定验证样本上，A 在表中各个时间点都更低；从第 1,000 到 10,000 步，两组差距缩小，但没有消失。第 500 步的差距在 B 上跳之前已经存在，因此不能由第 501 步的上跳造成。

为了检查测量而不是只相信日志，我用两组最终 checkpoint 和相同验证种子，重新运行这 25,600 个目标 token 位置的固定抽样验证。重算得到的 A、B loss 分别为 **1.428094828129** 和 **1.919713675976**，都与各自日志完全一致。这不是对完整验证集的评测。

### 4.2 前 500 步的训练 loss 变化

按照实验开始前记录的指标，我计算第 1～500 步训练 loss 的 499 个相邻差值，标准差采用总体标准差：

| 描述指标 | A：预热 | B：不预热 |
|---|---:|---:|
| 相邻训练 loss 差值的标准差 | 0.072661 | 0.099409 |
| 最大相邻变化的绝对值 | 0.308247 | 1.338903 |
| 最大变化的方向和位置 | 第 3→4 步下降 0.308247 | 第 2→3 步下降 1.338903 |

B 的这个简单变化指标更大，但我不能把它直接解释为“梯度爆炸”或“训练震荡”：B 最大的变化是一段**下降**，而不是 loss 突然增大；该指标还包含整体下降趋势及不同 batch 带来的影响。

事实上，B 最开始下降得更快。第 1 步两组训练 loss 均为 **9.408339**；第 3 步，A 为 **9.113965**，B 为 **7.196649**。这提醒我：没有预热不代表每一步都会立刻变差；在这次运行中，早期下降快并没有带来更低的后续验证 loss。训练 loss 是当前训练 batch 上的指标，不应直接当作验证集表现。

两组训练和验证日志中均未发现非有限 loss，且各自完成 10,000 步。但日志没有逐步记录梯度范数或参数更新范数，因此我不能判断具体是梯度、优化器状态还是其他因素造成了差距。

## 5. 结论与仍然不知道的事

**结论：** 在这组模型、数据、预算和单次初始化下，前 500 步学习率路径不同，与随后明显不同的验证 loss 轨迹相伴；在第 501～10,000 步学习率逐步相同后，差距仍持续到训练结束。该结果支持我原先“预热可能有帮助”的方向，但只能作为本次实验条件下的证据。

**我仍不知道：**

1. 完整去重验证集上的差距是否与固定抽样结果相近；目前只核验了相同的 25,600 个目标 token 位置。
2. 更换初始化和训练采样 seed 后，这种差距是否仍然稳定；目前只有一对运行。
3. 早期差距的具体机制是什么。已有日志没有梯度范数和参数更新范数，不能据此断言发生了梯度爆炸或某种特定的优化器故障。
4. 第 501 步上跳对最终差距贡献多少。第 500 步之前已出现的差距与这次上跳无关，但两组结束时的差距不能简单减去一个假定的“上跳影响”。
5. 验证数据中的近似重复是否影响结果；当前只排除了与训练原文完全相同的故事。

如果重做或继续验证，我会先用同一评测程序分别跑两组的完整验证集，并明确新评测口径；再在预算允许时增加配对随机种子。若重新训练，我会从开始就同时记录梯度范数和参数更新范数。也可以设计一组在第 500→501 步具有相同学习率上跳的 C 组，但这只能控制该数值条件；上跳的作用可能与当时模型状态相互影响。**本次没有运行 C 组。**

## 附录：任务 A 的推理优化小实验

这部分独立于上面的训练动态对照。我在 A 组 10,000 步模型上，比较了“计算所有位置的输出 logits”和“只计算最后位置的输出 logits”。这个优化在实验前已存在于生成代码中；我是在完成训练后测量它，而不是声称训练后才发明了它。

实验固定验证 token 流前 128 个 token，贪心生成 64 个 token，各预热 2 次、交替测量 10 轮：

| 生成路径 | 耗时中位数 | 吞吐量 |
|---|---:|---:|
| 完整位置输出投影 | 0.438394 秒 | 145.99 token/秒 |
| 只投影最后位置 | 0.402447 秒 | 159.03 token/秒 |

本次吞吐量约提高 **8.93%**；两条路径生成的 64 个 token ID 一致，初始输入最后位置的 logits 最大绝对差为 **0.00000763**。结果只覆盖一个固定输入，计时不含模型加载、分词和文本解码，不能推广为所有提示词和采样设置的保证。基准输入来自验证 token 流，片段中含故事边界；基准按固定数量生成，本次 64 个新 token 中未出现 EOS。
